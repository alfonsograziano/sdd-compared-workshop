# Data Model: Task Comments and Activity Log

Phase 1 output for [plan.md](./plan.md). Existing tables (`tasks`, `labels`, `task_labels`) are
unchanged.

## Entity: Comment (`comments`)

| Column | Type | Rules |
|---|---|---|
| `id` | integer, primary key, autoincrement | |
| `task_id` | integer, not null | FK → `tasks.id`, `ON DELETE CASCADE` |
| `body` | text, not null | markdown; trimmed; 1..10,000 characters (FR-002) |
| `created_at` | integer (`timestamp_ms`), not null | default `unixepoch('subsec') * 1000`; never changes |
| `updated_at` | integer (`timestamp_ms`), null | null until an edit changes the body; then the last edit time (FR-005, R5) |

Index: `comments_task_id_idx` on (`task_id`).

**Validation** (`src/lib/validation.ts`): `commentBodySchema = z.string().trim().min(1, "Comment
cannot be empty").max(10_000, "Comment is too long (max 10,000 characters)")`.

**Lifecycle**: created → (edited 0..n times) → deleted (hard delete by the user, or by cascade
when its task is deleted). No soft delete, no author (FR-020).

## Entity: Activity entry (`task_activity`)

| Column | Type | Rules |
|---|---|---|
| `id` | integer, primary key, autoincrement | |
| `task_id` | integer, not null | FK → `tasks.id`, `ON DELETE CASCADE` |
| `field` | text, null | one of `title`, `description`, `status`, `priority`, `labels`, `due_date`; null means "created the task" (FR-007) |
| `old_value` | text, null | see value encoding |
| `new_value` | text, null | see value encoding |
| `created_at` | integer (`timestamp_ms`), not null | default `unixepoch('subsec') * 1000` |

Index: `task_activity_task_id_idx` on (`task_id`).

**Value encoding** (R2):

| Field | Stored value | Displayed as |
|---|---|---|
| `title` | the title text | the text in quotes |
| `description` | the description markdown | "changed the description", with old and new text on demand (FR-012) |
| `status` | status key, for example `in_progress` | `STATUS_LABELS[key]`, for example "In Progress" |
| `priority` | priority key, for example `urgent` | `PRIORITY_LABELS[key]`, for example "Urgent" |
| `labels` | JSON array of label names, sorted, for example `["Bug","Docs"]` | added and removed names (FR-011) |
| `due_date` | `YYYY-MM-DD` or null | `formatDueDate`, or "no due date" when null (FR-010) |
| created (`field` null) | both null | "created the task" |

**Lifecycle**: append-only. Written only by the data layer, inside the transaction of the task
change. Never updated or deleted by the user (FR-014); removed only by cascade (FR-018).

**When a row is written**:

| Data-layer call | Rows |
|---|---|
| `createTask` | one row with `field = null` |
| `updateTask` | one row per provided field whose value differs from the stored one; labels compared as sets |
| `moveTask` | one `status` row when the status differs; none for a reorder in the same column |

## Derived: Task (`Task` type in `src/lib/tasks.ts`)

`Task = TaskRow & { labels: Label[]; commentCount: number }`. `commentCount` is computed by one
grouped count query in `listTasks` and `getTask`, never stored (R7).

## Derived: Timeline item (`src/lib/timeline.ts`)

```ts
type TimelineItem =
  | { kind: "comment"; id: number; at: Date; body: string; editedAt: Date | null }
  | { kind: "activity"; id: number; at: Date; field: ActivityField | null; oldValue: string | null; newValue: string | null };
```

Sorted by `at` ascending, then activity before comment, then `id` (R6). The page maps it to a
serializable view model with formatted times and sentences before passing it to the client.

## Relationships

```text
tasks 1 ──< comments        (ON DELETE CASCADE)
tasks 1 ──< task_activity   (ON DELETE CASCADE)
tasks >──< labels via task_labels   (unchanged)
```

## Migration

`drizzle/0001_comments_and_activity.sql`, generated by
`npm run db:generate -- --name comments_and_activity`. Contains only `CREATE TABLE comments`,
`CREATE TABLE task_activity` and their two indexes. Existing rows are untouched (FR-019).
`seed()` deletes from `tasks`, which cascades to both new tables because `createDb` turns on
`foreign_keys`.
