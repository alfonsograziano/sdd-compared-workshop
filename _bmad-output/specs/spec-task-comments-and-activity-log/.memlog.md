- (event) create from docs/FEATURE.md 'The request'; input rich enough to extract directly, no elicitation
- (note) mode: interactive; agent answers stops as the product owner who wrote FEATURE.md (no human at keyboard during the run)
- (capability) CAP-1 write a markdown comment on a task; success: comment appears in the task timeline, rendered as markdown, with when it was written
- (capability) CAP-2 edit a comment; success: new body shown, comment marked 'edited'; marker absent on never-changed comments
- (capability) CAP-3 delete a comment; success: comment gone from timeline after reload
- (capability) CAP-4 task changes recorded automatically: created, title, description, status, priority, labels, due date; success: each change yields one entry saying what changed, from what to what, and when (e.g. 'changed priority from Medium to Urgent')
- (capability) CAP-5 one timeline under the task description mixing comments and activity, oldest first / newest last; success: entries of both kinds interleave in time order
- (capability) CAP-6 comment count on board cards and list rows; success: count shown when >0, nothing shown when 0
- (capability) CAP-7 deleting a task deletes its comments and activity; success: no orphan comment or activity rows remain
- (constraint) single user: no author field, no permissions; 'my own comment' means any comment
- (constraint) recording must not depend on the user: every path that changes a task (detail form, board drag) produces activity
- (constraint) existing tasks, labels and task links survive the migration unchanged
- (decision) non-goal: notifications, mentions, reactions, threads, attachments - not in request
- (decision) non-goal: comments do not create activity entries; request lists only task fields
- (decision) non-goal: undo/restore from activity; log is read-only history
- (question) description change: show full old/new markdown, or a short line?
- (question) tasks existing before the migration have no 'created' entry: backfill one?
- (question) board reorder inside the same column: is it a recorded change?
- (question) saving with a value equal to the current one: record an entry?
- (question) label change: one entry per update with the before/after set, or one entry per label added/removed?
- (question) empty values (no due date, no labels, empty description): how are they named in 'from X to Y'?
- (question) what counts as 'edited' for a comment: any save, or only a changed body?
- (question) comment length limits and empty-comment handling?
- (assumption) migration-safety constraint is inferred, not stated: brownfield app holding real tasks
- (event) open questions presented to product owner
- (decision by user) description change reads as one short line 'changed the description'; old/new text still stored; full markdown would flood the timeline
- (decision by user) backfill one 'created' entry per existing task, dated at its created_at; every task gets a complete timeline
- (decision by user) reorder inside the same column is not a change; a drag to another column is a status change
- (decision by user) a save that leaves a field equal to its current value records nothing for that field
- (decision by user) labels: one entry per update with the sorted label names before and after; names, not ids, so old entries survive label rename/delete
- (decision by user) empty values read as 'none' (e.g. 'changed due date from none to Sep 24')
- (decision by user) comment is 'edited' only when a save changes its body; whitespace-only change trimmed away counts as no change
- (decision by user) comment body 1-20000 chars after trim, same ceiling as description; empty comment rejected
- (decision by user) story breakdown offered and declined: the request asks for one mixed timeline; shipping halves would not match it
- (event) pass 1 coherence: 7 capabilities each with intent+success; intents are WHAT; 3 constraints each rule out options; 3 non-goals; success signal testable - PASS
- (event) pass 2 preservation: every request claim mapped (timeline position, newest last, markdown, edit/delete, written time, edited marker, created + 6 fields, from/to/when, example wording, counts when >0, cascade, single user/no author/no permissions) - PASS; wrapper-only: 'Every framework gets this same text' (workshop ceremony)
